Companion to `PADHARO_BRAND.md`. Covers the three things that were left open.

## 1. Logo / icon / splash image files

### What's there now

**No SVG anywhere in the repo.** Everything is PNG/ICO.

- **Masters** (high-res PNG, the single source of truth) live in
  `enatega-multivendor-web/public/assets/brand/masters/`:
  | file | size | what it is |
  |---|---|---|
  | `padharo-icon.png` | 2048² | app icon — orange rounded square + mark |
  | `padharo-symbol.png` | 2048² α | the mark only (dome + P + pin + puddle), transparent |
  | `padharo-icon-transparent.png` | 2048² α | mark, maroon P — Android adaptive **foreground** (bg is orange) |
  | `padharo-icon-cream.png` | 2048² α | mark, cream P — **splash logo** (splash bg is maroon) |
  | `padharo-notification.png` | 512² α | white silhouette — Android notification icon |
  | `padharo-wordmark-cream.png` / `-maroon.png` | 1844×308 α | "Padharo" text — animated-splash wordmark |
  | `padharo-pin.png` | 1264×1668 α | the pin shape alone — animated-splash pin |
  | `padharo-splash-portrait.png` | 2160×3840 | full-bleed splash composition (maroon) |
  | `padharo-logo.png` / `padharo-logo-inverse.png` | 1600×443 α | horizontal lockup (mark + "Padharo") — feeds `padharo-logo.png` (800×222) that the in-app `<Logo>` / `AppLogo` components load |

- **49 raster files** the apps reference are generated by
  `scripts/generate-brand-assets.mjs`: app icons (`icon.png` 1024², `appIcon`,
  `adaptive-icon`), `splashTransparent`, notification icons, animated-splash
  `wordmark*/pin`, horizontal `padharo-logo.png` (web + admin), web
  `512/192/144/favicon.png/apple-touch-icon/splash-screen`, admin favicons, store
  `black.png` splash, and **4 `favicon.ico`** (multi-size, via bundled Pillow).
  `node scripts/generate-brand-assets.mjs --list` shows every target.

The current mark is a **clean approximation** of the supplied logo — same
concept and colours, not pixel-identical to the ornate original.

### Swapping in the real designed logo

1. Export your artwork to PNG (largest you have — the script only downscales) and
   drop it into `enatega-multivendor-web/public/assets/brand/masters/` with the
   **same filename and aspect ratio** as the file it replaces (table above). At
   minimum replace:
   - `padharo-icon.png` — the square app icon
   - `padharo-symbol.png` / `padharo-icon-transparent.png` / `padharo-icon-cream.png` — the mark, transparent (dark-P and cream-P variants)
   - `padharo-logo.png` / `padharo-logo-inverse.png` — the horizontal lockup
   - (optional) `padharo-wordmark-*.png`, `padharo-pin.png`, `padharo-splash-portrait.png`, `padharo-notification.png`
2. `node scripts/generate-brand-assets.mjs` — regenerates all 49 PNG/ICO targets.
3. For the three Expo apps: `cd <app> && npx expo prebuild --clean` so the native
   iOS `.xcassets` / Android `mipmap` + splash drawables are rebuilt from the new
   source PNGs. (Expo derives every density/size from the single `icon.png` 1024²
   and the splash `image` — you do **not** hand-cut per-density files.)

**Do it entirely by hand / with a service instead:**
- App icons + splash: put your 1024² `icon.png` and splash `image` at the paths
  in each `app.config.js` / `app.json` (`expo.icon`, `expo.android.adaptiveIcon.foregroundImage`,
  the `expo-splash-screen` plugin `image`), then `npx expo prebuild --clean`.
- Web favicons / PWA icons: https://realfavicongenerator.net → drop the outputs
  into each web app's `public/` (`favicon.svg`, `favicon.ico`, `apple-touch-icon.png`,
  `192.png`, `512.png`, `144.png`).

### `favicon.ico`

Generated — multi-size (16→256) via bundled Pillow, written to all four
`favicon.ico` locations (web + admin `public/` and `app/(localized)/`). If Pillow
isn't present the script skips this step and the PNG favicons still cover every
current browser.

### Files that still need YOUR raster (generator can't invent them)

- `enatega-multivendor-*/…/splash/assets/glow.png` — a soft radial glow used by the
  animated splash. Kept as-is; retint in code if you want (it's drawn behind the
  wordmark). Optional.
- Any photographic/marketing imagery (the About/Terms hero photos on web point at
  `images.deliveryhero.io` — swap for your own when you have them).

## 2. Bundle IDs / package names / URL schemes

**Left unchanged on purpose.** Current values:

| App | iOS `bundleIdentifier` | Android `package` | URL `scheme` | Expo `slug` |
|---|---|---|---|---|
| customer (`-app`) | `com.enatega.multivendor` | `com.enatega.multivendor` | `enategamultivendor` | `enategamultivendor` |
| rider (`-rider`) | `com.enatega.multirider` | `com.enatega.multirider` | `com.enatega.multirider` | `food-delivery-rider-multivendor` |
| store (`-store`) | *(see app.json)* | *(see app.json)* | `enatega-store` | `enatega-multivendor-restaurant` |

### What changing them costs

| Change | Consequence |
|---|---|
| `bundleIdentifier` / `package` | **A different app.** Existing installs won't update — users must re-download. New App Store / Play Console listing. Push credentials (APNs key, FCM `google-services.json` / `GoogleService-Info.plist`) must be regenerated for the new ID. Any Firebase project, Sentry project, deep-link domain association, OAuth redirect, or Maps API key that is keyed to the package must be re-registered. |
| `scheme` | Breaks existing deep links / OAuth callbacks that use `enategamultivendor://…`. Must update every place the scheme is referenced (Google/Facebook console redirect URIs, email templates, QR codes, `associatedDomains`). |
| `slug` | Changes the EAS project association / OTA-update channel URL. Do it together with `eas init` re-linking. |

### Recommendation

- **Pre-launch (nothing published yet):** change them now. Suggested:
  - `com.padharo.customer`, `com.padharo.rider`, `com.padharo.partner`
  - schemes: `padharo`, `padharorider`, `padharopartner`
  - Then in each app: update `google-services.json` + `GoogleService-Info.plist`
    from a Firebase project registered to the new IDs, re-run `eas init` if using
    EAS, `npx expo prebuild --clean`, and update every OAuth redirect URI.
- **Already on the stores:** do **not** change `bundleIdentifier`/`package`. Keep
  them; the visible name ("Padharo") is already updated. You can still change the
  `scheme` if you also fix every consumer of it, but it's usually not worth it.

Nothing in the codebase forces a decision — the apps build and run on the current
IDs. This is a release/ops call.

## 3. `enatega.com` / `info@enatega.com` in web legal copy

These sit in the **privacy policy and terms** translation strings (all locales),
e.g. `enatega-multivendor-web/locales/en.json`:

- `"privacy_policy_intro"` … *"we, Padharo, a brand of https://enatega.com/…"*
- `"privacy_policy_use_of_info"` / `"privacy_policy_access_info"` … *"email us at info@enatega.com"*

They're **real contact endpoints**, so they were left pointing at the working
address rather than a Padharo domain that may not exist yet.

### When you have a Padharo domain + inbox

Run this from `enatega-multivendor-web/locales/` (swap in your real values):

```bash
node -e '
const fs=require("fs");
const DOMAIN="https://padharo.com/";      // <-- your site
const EMAIL="support@padharo.com";        // <-- your inbox
for (const f of fs.readdirSync(".").filter(x=>x.endsWith(".json"))) {
  let s=fs.readFileSync(f,"utf8");
  s=s.replace(/https:\/\/enatega\.com\/?/g, DOMAIN)
     .replace(/info@enatega\.com/g, EMAIL);
  fs.writeFileSync(f,s);
}
console.log("done");
'
```

Also check (not brand-critical, but same idea):
- `enatega-multivendor-app` / `-rider` telemetry user-agent strings were already
  changed to `PadharoApp` / `Padharo-Rider-App`.
- API seed (`enatega-multivendor-api-mysql/prisma/seed.ts`) has a sample login
  password containing "Yalla" and console hints — cosmetic test data, leave or
  change freely.
- `market.nativebase.io` boilerplate description text in the Expo configs — replace
  with a real Padharo description when convenient.
